  ## Summary
  CRITICAL: 1 | HIGH: 0 | MEDIUM: 8 | LOW: 3

  #1 [CRITICAL] Admin endpoint with no authorization: account takeover (AP-03)
  - Files: config.py:26 · middlewares/auth.py:11, 36-38 ·
    controllers/user_controller.py:25-31, 65-91 · routes/user_routes.py:23-31
  - What's wrong: AUTH_REQUIRED is off by default. Even when it's on, the code
    only checks that a token is valid. It never checks who owns the resource or
    what role the caller has.
  - Confirmed by test: a regular user ran PUT /users/1 {"password":"hacked"} and
    got 200. The admin's password then became hacked. DELETE /users/1 also
    returned 200.
  - Fix: authorization per resource (a user can only change themselves unless
    they're an admin). Admin-only for deletes and /reports/* (P-03).

  #2 [MEDIUM] Weak plaintext credentials in the seed (AP-02): seed.py:23, 30, 37
  - The seed creates an admin with password '1234', plus 'abcd' and 'pass'. It
    also wipes every table and has no environment guard.
  - Fix: read passwords from env vars and refuse to run outside dev (P-02).

  #3 [MEDIUM] Coupling between layers (AP-07)
  - utils/validators.py:6 and controllers import domain exceptions from
    middlewares/error_handler.
  - user_controller.py:8 imports issue_token from the auth middleware.
  - task_controller.py:68 creates NotificationService inside the use case.
  - Fix: move the errors to their own domain module and inject the notification
    service in create_app (P-07).

  #4 [MEDIUM] Legacy MD5 hash, weak password policy, no login rate limit (AP-09)
  - models/user.py:41-45 still accepts unsalted hashlib.md5.
  - config.py:51 sets MIN_PASSWORD_LENGTH = 4.
  - /login has no rate limiting (user_controller.py:113-121).
  - Fix: P-09.

  #5 [MEDIUM] Missing type validation returns 500 instead of 400 (AP-12):
  utils/validators.py:61-62, 67-70, 74-75, 81-84, 128-133 ·
  task_controller.py:95
  - Confirmed by test: tags:{…}, description:{…} and category name:[…] all
    returned 500.
  - The search LIKE doesn't escape %/_.
  - Fix: P-12.

  #6 [MEDIUM] Aggregations done in memory and full table scans (AP-11):
  task_controller.py:37-39, 112-114 · report_controller.py:16-26, 58-60, 66-69, 
  77-84
  - The overdue check loads every task into Python.
  - The summary report runs 5 separate COUNT queries.
  - GET /tasks has no pagination.
  - Fix: P-11.

  #7 [MEDIUM] Outdated dependencies with known CVEs / legacy API (AP-14):
  requirements.txt:3, 5 · models/task.py:21-22 · middlewares/auth.py:3
  - flask-cors==4.0.0 and requests==2.31.0 have known vulnerabilities.
  - backref is legacy in SQLAlchemy 2.x.
  - itsdangerous is imported directly but not declared in requirements.txt.
  - Fix: P-14.

  #8 [MEDIUM] Insecure config defaults (AP-15): config.py:15, 20, 22
  - With no env var, SECRET_KEY is randomly generated per process, so tokens
    break on restart and across workers.
  - Defaults are HOST=0.0.0.0 and CORS=*.
  - Fix: P-02.

  #9 [MEDIUM] Synchronous SMTP inside the request (AP-16):
  notification_service.py:30-34 · task_controller.py:67-68
  - POST /tasks can block for up to about 10 s when notifications are enabled.
  - Fix: P-06.
